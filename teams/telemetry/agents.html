How MindSuite studies real use

Code shows what a system can do; telemetry shows what people really do with it. A team of 11 agents reads your logs and monitoring exports the way an experienced operations engineer would: load and peaks, speed and errors, which features are used and which never, and what that means for sizing the new system and planning the cut-over.

Four rules the whole system follows

No personal data keptClient addresses are only counted, never stored or shown. Query strings are dropped; ids, e-mail addresses and tokens in URLs become {id}.
Read-onlyAgents read exported logs and metrics. They never connect to your monitoring tools.
Every claim is citedEach finding points to the export it comes from (log lines by file and line only), or to the findings it is built on.
People decideAgents propose. Your operations team confirms, corrects or rejects each result.

The goal of the telemetry analysis

Size and plan the new system on measured use, not on today's servers or guesses. It ends in the Telemetry analysis report with capacity, service-level and cut-over targets.

How busy it isAverage and peak load, busiest hours, days and months.
How well it worksResponse times and errors, per endpoint.
What is really usedThe endpoints that matter, and those nobody calls.
What to aim forCapacity, service levels, freeze months, the cut-over window.

One finding, end to end

  1. The telemetry reader lines up 12 months of hourly Splunk counts and one day of NGINX log on one timeline.
  2. Load & peaks finds August to October twice as busy as the rest of the year, and the quietest four hours on Sunday night. Coverage notices ten days without data in February.
  3. Usage finds two endpoints in the code that nobody called all year; Errors finds the payment run failing a third of the time.
  4. The capacity & cut-over agent sets the target with 50% headroom over the peak, freezes August to October, and proposes Sunday 01:00–05:00 for the cut-over.
  5. Your operations team explains the February gap (a monitoring outage) and confirms the payment-run failures are a known batch problem.

Every agent

What is running today

All 11 agents run in the same MindSuite agent backend as the other teams. In MindSuite, open Record evidence → Telemetry → Run the telemetry agent team.

Nine rule-based agents always run and nothing leaves the backend machine. The business-use agent runs only with a Claude API key on the backend and your consent for that run; it sends endpoint names (cleaned) and traffic numbers, never client addresses or log lines.

Still to come: per-endpoint peaks over the year, user sessions and journeys (with a privacy review), and comparing the new system's telemetry against these targets after each migration wave.
