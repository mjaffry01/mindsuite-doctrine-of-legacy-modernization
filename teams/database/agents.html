How MindSuite studies your database

A second team of 14 agents studies the database the way an experienced DBA and data architect would: first the facts from the catalog, then the meaning, then the migration assessment. It works from the DBA's exports, never from your data. Every claim points to a line in the export and is checked before a person on your side confirms it. The code team is described here.

Four rules the whole system follows

Metadata onlyAgents read table definitions, stored code, jobs and statistics. Business data rows are never read; if an export contains some, they are counted and ignored.
Never connected to productionThe agents read export files your DBA produced with read-only tools. They never log in to the database.
Every claim is citedEach finding points to the export file and line, or to the findings it is built on, with its basis and confidence.
People decideAgents propose. Your DBA and experts confirm, correct or reject each result.

The goal of the database analysis

Turn the database into a validated picture you can plan a migration on: what data the system holds and how it is connected, where the business logic hides inside the database, what is risky, and how and in which order to move it. It ends in the Database analysis report, with every statement linked to its evidence and confirmed by a named person.

What data it holdsTables, keys, data clusters, size, personal data.
Where the logic livesProcedures, packages, triggers, jobs, CHECK rules, calls out of the database.
What is riskySupport status, admin accounts, links to other databases, engine lock-in, design gaps.
How to migrateEffort per data domain, the order, and the overall approach.

Prefer a schema-only export. If a file contains data (INSERT … VALUES), the agents count those statements, never read or send them, and ask for a schema-only export.

How the analysis runs, step by step

The same 9 steps as the code team. Step 3 runs six agents in parallel; the jobs agent follows the stored-code agent so each job can point to the program it runs. Click an agent name to see it in the diagram.

What the export alone cannot tell, and how it is handled

Who owns each table, whether a rule is still wanted, what generic columns (ATTRIBUTE1…) hold, whether statistics are current, and what is on the other side of a database link. The agents do not guess these: they become questions for your DBA and experts.

How the agents communicate

Exactly like the code team: no free chat. Agents exchange five kinds of messages (task, finding, hand-off, verification, question) through the orchestrator and the shared evidence store, so every step is recorded and can be traced. Later agents build on earlier findings by their id.

Example of a finding as stored (simplified):

{
  "id": "rel-10",
  "agent": "schema-and-relationships",
  "kind": "constraint-rule",
  "claim": "DELIVERIES: STATUS IN ('NEW','TESTED','PAID','REJECTED')",
  "citation": "schema.sql:32",
  "basis": "observed in the export",
  "confidence": "high",
  "verified": "accepted",
  "status": "waiting for a person to confirm"
}

One finding, end to end

  1. The catalog reader reads the schema export and the catalog result: Oracle 12c, 9 tables, 3 programs and a trigger, a nightly job, 6.3 GB.
  2. Schema & relationships finds that DELIVERIES, GROWERS, FIELDS, QUALITY_TESTS and PAYMENTS form one data cluster. Stored code finds that SETTLEMENT_PKG writes PAYMENTS and DELIVERIES, and that a second program also writes PAYMENTS.
  3. Because it writes key tables, is complex and is run by the nightly job, the orchestrator puts SETTLEMENT_PKG on the reading list.
  4. The database business-rules agent reads it and writes: "Grade A deliveries with moisture below 14% get a 10% higher price", citing the exact lines.
  5. The verifier re-opens those lines, and a second model confirms they say this. The migration assessment scores the cluster and suggests it as the first domain.
  6. Your DBA confirms the rule and adds: "the 10% bonus was reduced to 8% last season" — the conflict goes to the business owner.

What is running today

All 14 agents run in the same MindSuite agent backend as the code team. In MindSuite, open Record evidence → Database → Run the database agent team (or 02 Code analysis → Run the database agent team), choose the export files, and watch the 9 steps run.

The 11 rule-based agents always run and nothing leaves the backend machine. The Claude-powered steps run only with a Claude API key on the backend and your consent for that run: then the picked programs (with any password lines removed), table and column names and the findings are sent — never data rows. Every request is listed in the result.
