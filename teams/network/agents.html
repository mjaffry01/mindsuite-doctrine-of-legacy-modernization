How MindSuite studies your network edge

Every way into and out of the system has to keep working on the day of the move. A team of 11 agents reads configuration and inventory exports and finds what the Network edge & partners card promises: load balancers, API gateways, CDN and DNS entries, TLS certificates and expiry, partner connections (SFTP, EDI, VPN) and firewall openings. Nothing is contacted.

Four rules the whole system follows

Exports onlyConfiguration files, zone files, rule exports and lists. No host is scanned or contacted.
Keys never shownPasswords, VPN pre-shared keys and private keys are reported as file and line only.
Every claim is citedEach finding points to the configuration line, record or rule it comes from.
People decideAgents propose. Your network team confirms, corrects or rejects each result.

What the agents need from your network team

GiveHow (read-only)
Load balancers and proxiesnginx -T, the HAProxy configuration, kubectl get ingress,services -A -o json, the cloud inventory (load balancers, gateways, CDN)
DNSThe zone file, or a CSV with name, type, value, ttl
TLS certificatesopenssl s_client -connect host:443 </dev/null | openssl x509 -noout -subject -issuer -enddate -text per public host
Partner connectionsA CSV: partner, host, port, protocol (SFTP, FTP, AS2, VPN, API), direction, owner
Firewall openingsA rule export as CSV: name, source, destination, port, protocol, action, description

What is running today

All 11 agents run in the same MindSuite agent backend as the other teams. In MindSuite, open Record evidence → Network edge & partners → Run the network edge & partners agent team.

Nine rule-based agents always run and nothing leaves the backend machine. The edge-map agent runs only with a Claude API key on the backend and your consent for that run.
