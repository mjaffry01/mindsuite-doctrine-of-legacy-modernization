How MindSuite studies your incidents

A system's tickets show where it really hurts. A team of 11 agents reads your incident, change and problem exports and finds what the Incidents & changes card promises: where the system breaks most often, recurring problems, change frequency and failed changes. People's names are never kept.

Four rules the whole system follows

Titles and dates onlyNumber, short description, component, priority, state and dates. Descriptions, comments and work notes are not read.
No namesCaller, assignee and reporter columns are only used to remove those names from titles. Tickets are cited by file and line, never quoted.
Every claim is citedEach finding points to the ticket rows it is counted from.
People decideAgents propose. Your service desk and problem manager confirm, correct or reject each result.

Every agent

What is running today

All 11 agents run in the same MindSuite agent backend as the other teams. In MindSuite, open Record evidence → Incidents & changes → Run the incidents & changes agent team.

Nine rule-based agents always run and nothing leaves the backend machine. The failure-story agent runs only with a Claude API key on the backend and your consent for that run.
